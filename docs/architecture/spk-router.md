# VoiceMixerSpkRouterの構造

現在版はv1.0.8。動作の正本は[仕様と利用方法](../spk-router.md)。エントリーポイントは `src/main.rs`、専用実装は同じ場所の `spk_router/` に置く。

## ファイルと責務

| モジュール | 責務 |
|---|---|
| `cli.rs` / `instance.rs` | 引数解析、名前付きmutex、既存常駐へのIPC |
| `application.rs` | UI巡回、非同期適用の応答、確定済み状態の出力、ワーカー終了待ち |
| `config.rs` / `key_binding.rs` | 旧設定の補完、表示・起動・用途名、6操作のキーと検証 |
| `catalog.rs` | デバイス・アプリ候補、保存先と名前順の保持 |
| `state.rs` | 操作と状態の型。CLI指定は冪等、取得キーはトグル |
| `engine.rs` | 音声設定と保存のトランザクション、旧設定復旧、再試行 |
| `engine/routing.rs` | 実デバイス解決、循環拒否、1→2優先の重複抑止、Graph |
| `engine/browser.rs` / `engine/session.rs` | 待受、入力・出力の寿命、古いPCM破棄、音声イベント |
| `telemetry.rs` | 既存イベントから50ms単位のピークを集約し、最新の1秒履歴を共有 |
| `ui.rs` / `ui/commands.rs` | 画面の所有、設定中の操作排他、IPC番号と内部操作の変換 |
| `hotkeys.rs` / `ui/key_registration.rs` | 共存・上書きとMSTSC追従、保存成功後の割当確定 |
| `ui/browser_help.rs` | オフライン案内の探索、URLのパス符号化、既定ブラウザ起動 |
| `ui/overlay.rs` / `ui/overlay/drawing.rs` | 可視候補の均等配置とヒット領域、表示期限・部分描画・各メーターと状態・ドラッグ |
| `ui/settings.rs` / `ui/tray.rs` / `ui/native.rs` | 編集内容と標準タブ2枚、トレイとモード別アイコン、Win32資源の寿命 |

起動・配備のCargo呼出しは `dev/scripts/SpkRouter.Common.ps1` を共有し、Cargo設定から出力先を求める。

## 変更時に守る境界

- 取得3候補＋停止・出力2系統・出力キーなし・停止時は取得停止を維持する。`input_enabled`の旧設定既定は全ON。OFFの候補は非表示にし、キー・IPCからも選択しない。選択中の候補をOFFにして適用する場合は停止し、設定値は保持する。マイク版の3出力・P2T・RVC・停止中の入力取得を持ち込まない。
- IPCの設定表示100・終了101・モード指定201〜204、キー配列先頭4操作を互換契約として保持する。設定・表示のキーは末尾へ未割当で追加する。画面の順序を保存順の変更へ流用しない。
- キーをOSで予約しない。専用フックは合成入力を除き、共存では透過し、上書きでは一致主キーの押下・反復・解放を抑止する。モードなしの旧設定は共存、新規既定はShift+F1〜F4。使用OFFの入力は検出用の複製だけ無効にし、保存割当を保つ。抑止状態は割当更新をまたいで解放まで保持し、OSの非同期状態で消さない。通知配送失敗時の新規押下は透過する。Alt/Windowsの単独メニューを防ぐ補助入力は注入として区別し、自分の操作対象にしない。
- 登録途中や保存失敗で旧割当を変えない。設定中もキー操作を受け付け、画面・IPCからの編集制限とは通知元で分ける。取得4操作・設定表示・表示切替だけをキー通知として許可し、出力キーは追加しない。検知時の通知世代を保持し、割当更新をまたぐ古い通知は破棄する。編集開始・終了では世代を変えず、有効なキーを失わない。通常権限MSTSCの前景切替直後と約500msごとにフック順序を更新し、その間GetAsyncKeyStateでの補正をしない。
- 設定画面を開く操作だけが復元・前面化を行う。表示中はSW_RESTOREを繰り返さず、編集フォーカスと選択範囲を維持する。IsDialogMessageへ渡すのは当該画面・子コントロール宛てのキーだけ。非表示起動フラグでも明示的な設定表示を行う。
- 設定適用中もUIを巡回する。音声ワーカーで候補の反映と保存を行い、失敗時は旧音声設定へ戻す。成功応答後だけキーとUIの確定値・編集基準を更新する。成功後も同じタブと編集排他を維持し、閉じるまで設定画面を保持する。適用中の編集を無効にし、解除時は各キー行の有効状態に従ってグレーアウトを戻す。通常操作の待機中は最新の切替要求を保持し、終了は受け付ける。
- キー・用途名・表示・起動方法だけなら音声を再起動せず、デバイスの障害中も保存できる。用途名は表示専用で、音声ノード名やデバイスIDに使わない。
- キーで変わった取得元は適用時に維持する。表示方法だけは未編集なら実行値に追従させ、未適用の変更を検出した欄は適用または閉じるまで保持する。他の入力値・キー選択・タブは実行状態の更新で変更しない。
- 音声の稼働状態と操作の保存エラーを分ける。復旧した経路を保存失敗だけで故障扱いにしない。旧経路の復旧も失敗した場合はエラー・再試行へ進む。
- 既定値を実IDへ解決して循環を検査し、約2秒ごとに再確認する。同一保存IDのON出力は拒否し、別IDの同一実デバイスは1→2優先で抑止する。保存したON/OFFは維持する。
- 取得元変更では出力から止め、旧バッファを解放する。出力だけの変更は取得元と他方の出力を維持する。停止では全取得・出力ノードを止め、使用ONのブラウザ待受だけを残す。ブラウザ使用OFFでは待受を解放し、再ONで復旧する。ブラウザ再選択前に古いPCMを捨てる。
- メーターは既存音声イベントだけを使い、選択入力と出力1・2の3系列を最新スナップショットで共有する。無効ノードのイベントを集約せず、非選択入力の追加取得をしない。欠測・500ms以上の停止・モード不一致の古い値を表示しない。メーターは各ボタンの真下で、入力・出力の2矩形だけ再描画する。メーターや秒数更新を表示期限・再表示に結び付けない。
- 完成画像の一括転送と必要矩形だけの再描画を守る。描画とクリックは同じ矩形を使う。Win32の同期呼出し中はコールバックが借りるロックを保持しない。
- 終了では音声ワーカーをjoinし、キー監視、設定画面、トレイ・常駐画面・アイコン・クラスの寿命を守る。設定画面が借りるアイコンを先に破棄しない。

## 検証と配備

```powershell
cd C:\develop\VoiceMixerSpkRouter
cargo test --manifest-path .\Cargo.toml --bin voicemixer-spk
cargo test --manifest-path .\Cargo.toml --bin voicemixer-spk -- --ignored --test-threads=1
cargo build --manifest-path .\Cargo.toml --bin voicemixer-spk
pwsh -NoProfile -File .\dev\scripts\tests\Test-SpkRouterLifecycle.ps1 -Executable .\target\debug\voicemixer-spk.exe
pwsh -NoProfile -File .\dev\scripts\tests\Test-SpkRouterUi.ps1 -Executable .\target\debug\voicemixer-spk.exe
```

カスタムCargo出力先では `cargo metadata --format-version 1 --no-deps` の `target_directory` を使う。GUI・実EXE試験は他のSpkRouterを終了し、専用設定・出力OFFで実行する。UI試験の `-Screenshots` はWindows UI検証ツールキットを使い、対象窓だけ撮影する。撮影・自動操作時は事前に操作を控えるよう案内する。

通常試験は旧設定、キー移行、経路、重複、音声・保存の失敗時復旧、PCMからの実イベントと停止を検証する。GUIは配置・編集保持・フォーカス・キー予約への非干渉を検証する。実EXEは保存失敗・排他・表示期限・再起動を検証する。実フック試験だけテストビルドの注入許可を有効にし、専用Ctrl+Shift+F24の通知と後続フックへの到達・抑止・解放を検証する。製品ビルドは注入入力を検出対象にしない。この試験とコマンド通知試験は、物理キーの測定や実MSTSC接続の代用と記録しない。

低レベルフックの抑止とタイムアウトの制約は[Microsoftの仕様](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)、補助入力の権限境界は[SendInputの仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)に従う。保護されたOS操作・先行フック・権限境界までの抑止を保証しない。

配備前に元のEXE・設定と稼働状態を退避し、通常終了を確認してからReleaseビルド・配備する。既存Startupは再登録せず、設定のハッシュと単一プロセス・版・状態を確認し、必要な元の状態へ戻す。資料だけの変更ではアプリの版更新・再配備を行わない。自動試験・測定・ユーザー確認・未測定範囲を[検証記録](../../dev/testing/spk-router-results.md)へ追記する。
