# VoiceMixerSpkRouter v1.0.15 設計

状態：実装・検証済み。対象は経路衝突の事前表示、待機理由の区別、認証トークンの伏せ字。親Toys、公開・配備、音声転送の既定値、キー設定、画面全体の再配置は対象外。

## 1. 経路衝突の事前表示

- 基本設定の入力スピーカー・出力デバイス・入力の使用状態・出力の有効状態を変えたときに、編集値から判定する。設定を開いたとき、候補の再読込・初期値への復帰・実行モードの変化でも更新する。検査は音声の取得・転送・設定保存を開始しない。
- 入力スピーカーが使用ONの場合、入力と出力を同じ実デバイスIDに解決して比較する。「既定のデバイス」「既定の通信デバイス」と個別選択が同じ実機を指す場合も検出する。候補名だけでは比較しない。設定表示中にWindowsの既定先が変わる場合も再評価し、解決失敗や未接続は「未確認」として扱う。
- 出力ONで現在の取得モードが再生デバイスなら、該当する出力欄をエラー表示し、既存のメッセージ領域に「出力1：入力と同じデバイスです。別のデバイスを選択してください」のように表示する。両出力が該当すれば両方を示す。出力OFF、停止中、アプリ／ブラウザ取得中は「この出力は再生デバイス取得と同時に使えない」という予告として示し、他の設定の適用は妨げない。入力スピーカー使用OFFなら循環予告の対象外。
- 出力同士は既存の扱いを維持する。同一保存IDの両出力ONは既存の検証で拒否。論理IDは異なるが同じ実機に解決される場合は「出力1を優先」と知らせ、保存値やON/OFFは自動変更しない。
- 共通の経路判定を使い、事前表示と実行時の循環防止を揃える。「適用」、オーバーレイからのON、キー・CLIからのモード切替では、その時点の実機で再検証する。事前確認後にOSの設定が変わっても安全判定は省略せず、拒否時は既存の設定・経路を維持する。

## 2. 待機・未選択・出力状態の区別

表示文言から原因を逆算せず、音声処理から機械判定用の理由を渡す。既存のmode・phaseの値、管理契約、CLIの終了条件は維持する。必要な状態は任意項目として追加し、CLIにも秘密を含めない。

| 確認できた状態 | 短い表示 | 詳細の案内 |
|---|---|---|
| 使用可能だが別の入力を選択中 | 未選択 | 取得元を選ぶと切り替わる |
| 出力スイッチがOFF | 出力OFF | 入力取得と元音の再生は別 |
| 対象アプリのプロセスが存在しないと確認 | アプリ起動待ち | 対象アプリを起動 |
| 対象アプリは稼働、取得開始の準備中 | 準備中 | 取得開始を待つ。無音の断定はしない |
| 指定ストリームが未接続・切断 | タブ接続待ち | 拡張でキャプチャを開始し、接続設定とキーを確認 |
| 接続を確認したが新しい音声データなし | 音声待ち | キャプチャが開始され、対象タブで再生中か確認 |
| 待受失敗・デバイス切断・取得エラー | エラー | 既存の障害情報を表示。接続待ちへ丸めない |
| 理由を特定できない待機 | 待機中 | アプリ未起動・認証失敗などを推測で断定しない |

オーバーレイは現行のメーター欄と幅を使用し、長い理由と対処はツールチップまたはトレイで確認できるようにする。入力使用OFFは既存どおりオーバーレイに出さない。無音のPCMが届く状態、PCM未着、レベル測定待ちを区別し、理由が変わったときに表示を更新する。

## 3. 認証トークンの伏せ字

- 基本設定を開くたびに、編集欄はパスワード表示で開始する。隣に「表示／隠す」「コピー」を置く。説明用の常設キャプションは追加せず、必要な説明はツールチップに置く。
- 「表示」でその欄だけ一時表示。「隠す」、設定画面のフォーカス喪失、別タブへの移動、適用、閉じる操作で再び伏せる。表示状態は保存しない。隠した状態のまま編集できる。
- 「コピー」は明示操作時だけ、編集中の欄のトークンをクリップボードに入れる。未適用値は「適用するまで接続には使われない」とツールチップで示す。通知は「コピーしました」だけとし、値を表示しない。コピー後に他アプリが入れた内容を消す危険があるため、クリップボードは自動消去しない。
- マスク切替・コピー・タブリセットでトークンの値を再生成、保存、送信しない。ログ・診断・エラー・テスト画像に実トークンを含めない。これは画面上の露出対策であり、保存ファイルの形式や既存拡張との認証契約は変えない。

## 受入条件

- 実機IDの別名一致・別機器・未接続、出力ON/OFF、停止／アプリ／ブラウザ取得中を組み合わせ、エラーと予告が仕様どおりになる。経路変更なしで事前表示され、適用・切替での循環防止も残る。
- アプリ未起動から起動、ブラウザ未接続から接続・PCM到着・切断、待受エラー、全出力OFFを切り替え、短い表示と詳細理由が一致する。音声の聴感と状態判定の検証は別々に記録する。
- テスト専用トークンで初期マスク、明示表示、フォーカス喪失・タブ切替での再マスク、コピー、保存せず閉じた場合の保持を検証する。トークンを含まないログで結果を残す。
- 既存のオーバーレイの設定ボタン常時着色、タブ別リセット、左右修飾キー設定の回帰を確認する。

## 実装順序

1. 読み取り専用の経路判定を共通化し、基本設定の該当欄に接続する。
2. 待機理由を音声状態から取得し、オーバーレイ・詳細表示へ反映する。
3. トークン欄のマスク・表示・コピーを追加する。
4. 版定義を同期し、通常回帰・Win32操作・対象機器で検証する。

## 実装・検証結果

- 通常回帰64件、Win32回帰8件が成功。実設定ウィンドウで、同じ実機に解決される候補を使って予告・有効な経路のエラー表示・使用OFF時の解除を確認した。実行時の循環拒否、二重送信抑止、旧経路の復旧は既存回帰で確認した。
- ブラウザの未接続→接続・PCM未着→無音PCM到着→切断を実バックエンドのテストで確認。従来のphaseとCLIの成功条件は維持し、任意のwait_reasonを追加した。物理出力の聴感、Chrome/Edgeの実タブ、対象アプリを起動する通し操作は未確認。
- 実Win32の設定欄で初期マスク、表示／隠す、タブ切替と非アクティブ化の再マスクを確認。コピーは試験用値がコピー先に渡ることを注入先で照合した。既存のクリップボードは上書きしていない。分離したクリップボードの作成はOSがアクセス拒否したため、OSクリップボードへの書き込み・他アプリへの貼り付けは未確認。
- デバッグビルド成功。v1.0.15の設定窓を起動し、応答と設定ファイルのSHA-256が起動前後で同一であることを確認した。
