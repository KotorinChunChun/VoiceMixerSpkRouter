# VoiceMixerSpkRouter v1.0.16 設計

状態：実装・検証済み。対象は隔離テスト起動、設定案の経路検証、出力切替、適用結果のJSON取得。配布EXE、既存CLI、Toys管理契約2の挙動は維持する。

## 隔離テスト起動

- 開発ビルド専用の `--test-session` を追加する。引数解析直後に専用分岐し、通常の単一起動mutex、既存ウィンドウへの転送、Toys管理パイプ、設定パスの解決より先に処理する。この引数と `--config`、`--mode`、`--settings`、`--stop` 等の通常引数の併用は拒否する。初期化が失敗しても通常起動にフォールバックしない。
- 試験ごとに一意なセッションIDと新規の私用一時領域を作成する。既存ファイル、実設定からの読み込み・コピー、任意パスの指定を許可しない。実トークンを生成・取得せず、設定永続化の試験は試験値だけを使う。一時設定は終了時に所有確認して回収する。テストログは版別logsに残し、設定内容・トークン・絶対パスは応答に含めない。
- GUI、トレイ、グローバルキー監視、Windowsの自動起動登録、通常のブラウザ待受を起動しない。通常のプロセスは稼働したままでよい。OS音声デバイス・アプリ・ブラウザに接続せず、デバイスIDと別名の解決は内蔵の決定的な試験データを使う。OSを操作する実機試験は別に行う。
- 子プロセスの標準入力・出力だけで操作する。ソケットや追加パイプは設けない。標準入力EOFまたは `shutdown` で当該子だけ終了。要求失敗やタイムアウトで通常の常駐にコマンドを送らない。テストランナーが強制終了する場合も、自分が生成したPID・パス・開始時刻を照合した子だけが対象。

## JSON契約

1行1JSONのUTF-8。起動時に `ready` イベントを1行返し、以後、要求1件に応答1件。スキーマ版1、要求ID、操作名、結果、セッションID、適用済みrevisionを返す。応答順は要求順。標準出力はJSONのみ、標準エラーは秘密を含まない診断用。入力上限は1行64 KiB、要求は直列とする。上限超過・不正JSON・未知操作・フィールド・旧revisionはコードで区別し、状態を書き換えない。個別操作エラーは応答で返し、起動失敗・セッション障害はプロセス終了コード非0。テストランナーは期待する拒否と不意の失敗を区別して終了コードを決める。

| 操作 | 要求・応答 |
|---|---|
| `status` | 稼働中の子から取得。モード、phase、設定上の出力ON/OFF、実際に採用される出力経路、revisionを返す。通常の状態ファイルは読まない。 |
| `validate-route` | 設定案と明示モードを受け取り、フィールド、重大度、理由コード、解決した試験デバイスIDを返す。現在のrevision・設定・実行状態を変更しない。 |
| `set-output` | `output: 1` または `2`、`enabled: true/false` と期待revisionを指定。同じ値を再指定しても反転しない。実行時と同じ検証・適用順を使う。 |
| `apply` | 編集案と期待revisionを受け取り、適用の確定後に `applied`、`unchanged`、`rejected`、`failed` を返す。成功時は新状態、拒否・失敗時は理由と変更後の実状態を返す。 |
| `shutdown` | 応答後、この試験セッションだけを正常終了する。 |

設定案は現行の試験設定に対する許可リスト方式のパッチ。対象は取得モード・使用する入力・試験用の入力ID・出力1/2のIDとON/OFF。ブラウザ認証値・パス・既存設定の全量取込は受け付けない。操作とJSON例は実装時にdocsへ記載する。

例：
```json
{"schemaVersion":1,"requestId":"out-1","command":"set-output","expectedRevision":0,"output":1,"enabled":true}
```

経路衝突で拒否した例：
```json
{"schemaVersion":1,"sessionId":"fixture-session","requestId":"out-1","command":"set-output","result":"rejected","revision":0,"issues":[{"code":"route_loop","field":"outputs[0].deviceId","severity":"error"}],"state":{"mode":"device","outputsEnabled":[false,false]}}
```

## 実装上の境界

- v1.0.15の実ID解決・経路衝突・重複抑止を共有し、解決器と音声・保存の実行部だけを試験用へ差し替える。試験CLI専用の別判定を作らない。
- 停止中や出力OFFなど将来起きる衝突は予告、現在の経路の循環や不正設定は拒否。別名で同じ出力先を指定した場合の出力1優先は、設定上のONと実際に使う出力を分けて返す。適用時に再検証する。
- revisionは確定した変更だけで進める。設定・実行状態・永続化を既存の適用処理と同じ順で扱い、失敗時は旧状態を保つ。復旧まで失敗した場合は `rollback_failed` と明示し、旧経路を保持したとは返さない。テストでは音声適用失敗・保存失敗を注入できるようにする。
- このIFで保証するのは、判定・状態遷移・保存／復旧・JSON応答。画面の配置・描画、実クリップボード、物理キー、実タブの接続、物理出力の聴感は別のWin32・実機試験とする。

## 受入条件・実装順序

1. 通常版を起動したまま隔離子を2つ並行起動。片方の適用と終了、異常終了、不正引数を試し、他方の状態と通常版のPID・管理応答・設定ハッシュ・音声モードが不変であることを確認する。
2. 経路検証で正常、実IDの別名一致、未接続、出力OFF、出力1優先を再現。JSONの理由と重大度、判定前後の不変性を確認する。
3. 出力1/2の独立操作、同値指定、循環による拒否、適用結果、古いrevision、音声適用・保存・復旧の失敗をCLIから検証する。
4. EOF・終了・起動失敗時の片付け、出力に実トークンが混ざらないこと、通常CLIとToys管理契約の回帰を確認する。版番号の変更・ビルド・コミットは実装工程で行う。

## 実装・検証結果

- 通常経路の判定と適用トランザクションを共有し、隔離時は内蔵デバイス表と試験用保存先を使った。OSのオーディオ、GUI、通常IPCへの接続は行わない。
- 通常回帰64件、隔離CLI受入31件成功。通常v1.0.15のPID 1792を停止せず、別出力先に作ったv1.0.16の子2つを同時起動して確認。通常版のPID・開始時刻・EXE・管理契約応答・設定ハッシュ・音声モードは不変。
- 実IDの別名による循環、未接続、出力OFF時の予告、出力1優先、設定案検証時の不変性、出力1/2の独立操作、同値、旧revision、適用時の再検証、音声・保存・復旧失敗を確認した。復旧失敗の応答は有効経路を不明とし、同じ設定を再適用できる。
- 不正JSON・長すぎる行・許可外項目、通常引数併用、起動失敗、EOF・正常終了、試験子の強制終了を検証した。強制終了時に残った一時領域は試験ランナーが所有を確認して片付けた。
- 通常管理IPCは応答を待ち受けてから読み取り専用のstatusを送信し、比較に使用した。通常の管理側コードは変更していない。
- 実機の音声出力・GUI・ブラウザ実タブ・物理キーは今回の隔離試験の対象外。通常版への差し替え、配布、公開は行わない。
